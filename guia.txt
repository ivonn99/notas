# Archivo del proyecto — Sistema Notas de Crédito (Django)

Documento de referencia **antes de eliminar el repositorio local**. Resume qué hacía la app, rutas, roles, base de datos Supabase y estructura de plantillas.

> **Seguridad:** no guardes contraseñas reales en este archivo. Las credenciales viven en **Supabase** y en tu archivo **`.env`** (local / Render). Si alguna clave se compartió en chat o por error, **rótala** en el panel de Supabase.

---

## 1. Qué era el sistema

- **Framework:** Django 4.2 (`proyecto/` + app `pagina/`).
- **Nombre comercial en UI:** DMH — Distribuidora de Medicamentos Homeopáticos.
- **Función:** gestión de **notas de crédito**, usuarios por **rol**, **rutas**, **importación** de reportes (CSV/TSV/Excel con pandas/openpyxl), **seguimiento** y **comentarios** en notas.
- **Autenticación:** sesión Django (`login` / `logout`), usuario personalizado `pagina.Usuario` (tabla `usuarios`).
- **Autorización:** decorador `rol_requerido` en `pagina/decorators.py`; `is_superuser` de Django tiene acceso total.

### Roles (`Usuario.rol`)

| Código     | Etiqueta              |
|-----------|------------------------|
| `VENDEDOR` | Vendedor               |
| `CREDITO`  | Crédito y Cobranza     |
| `ADMIN`    | Administrador        |

## 3. Supabase / conexión a base de datos

### 3.1 Dónde se configura en Django

Archivo: `proyecto/settings.py`.

- **Opción A (recomendada):** variable de entorno **`SUPABASE_DB_URL`** — cadena `postgresql://...` (configurada en tu backend).
- **Opción B:** variables sueltas: `SUPABASE_DB_HOST`, `SUPABASE_DB_NAME`, `SUPABASE_DB_USER`, `SUPABASE_DB_PASSWORD`, `SUPABASE_DB_PORT` (SSL `require`).
- **Sin Supabase en entorno y `DEBUG=True`:** SQLite local `db.sqlite3` en la raíz del proyecto (solo para desarrollo).
- **Sin Supabase y `DEBUG=False`:** el settings endurecido exige configurar Supabase (no usar SQLite en prod).

### 3.2 Dónde están las “contraseñas” (sin escribirlas aquí)

| Secreto | Uso | Dónde obtenerlo / guardarlo |
|---------|-----|-----------------------------|
| Contraseña de BD | Conexión PostgreSQL | Panel Supabase → proyecto → **Connection string** o **Reset password** del rol de BD. |
| `SUPABASE_DB_URL` | URL completa con usuario y password | Copiar de Supabase; pegar en `.env`, Render, etc. **No commitear.** |
| `SECRET_KEY` | Firmas de sesión Django | Generar con Django; guardar solo en env. |
| Usuario/contraseña de **login de la app** | Acceso web | Tabla `usuarios` (campo `password` = hash Django). Cambiar con admin Django o `createsuperuser` / formularios. |

**Después de borrar el proyecto:** conserva en un gestor de secretos:

1. URL o variables de Supabase.  
2. `SECRET_KEY` de producción si sigues usando la misma BD con otro stack.  
3. Lista de usuarios administrativos (sin contraseñas en claro).

## 4. Estructura de tablas (modelos Django → PostgreSQL)

Nombres de tabla = `db_table` en `pagina/models.py`.

### 4.1 `usuarios` (`Usuario` — extiende `AbstractUser`)

Campos propios destacados: `nombre_completo`, `rol`, `activo`, `created_at`.  
Incluye campos estándar Django: `username`, `password`, `email`, `first_name`, `last_name`, `is_superuser`, `is_staff`, `is_active`, `date_joined`, etc.  
Relación M2M con `rutas` vía `usuario_rutas`.

### 4.2 `rutas` (`Ruta`)

`codigo` (único), `nombre`, `descripcion`, `activa`, `created_at`.

### 4.3 `usuario_rutas` (`UsuarioRuta`)

`usuario_id`, `ruta_id`, `created_at`; único `(usuario, ruta)`.

### 4.4 `notas_credito` (`NotaCredito`)

Campos principales: `serie_folio`, `fecha_nota`, `cliente`, `empresa` (`DISTRIBUIDORA` | `RODRIGO`), `ruta_id`, `usuario_id` (vendedor asignado, opcional), `usuario_vendedor_pv`, `monto`, `abono`, `saldo` (recalculado en `save`: `monto - abono`), `estado` (`PENDIENTE` | `RESUELTA` | `CANCELADA`), `resuelta_automaticamente`, `requiere_atencion`, `fecha_corriente`, `fecha_ultima_actualizacion`, `fecha_resolucion`, `created_at`.  
**Unicidad:** `(empresa, serie_folio)`.

### 4.5 `historial_notas` (`HistorialNota`)

Auditoría de cambios por nota: `nota_id`, `usuario_id`, `campo_modificado`, `valor_anterior`, `valor_nuevo`, `observacion`, `created_at`.

### 4.6 `aclaraciones` (`Aclaracion`)

Comentarios en nota: `nota_id`, `usuario_id`, `comentario`, `tipo` (`COMENTARIO` | `ACLARACION` | `SEGUIMIENTO`), `leida`, `created_at`.

### 4.7 `documentos` (`Documento`)

Adjuntos: `nota_id`, `usuario_id`, `nombre_archivo`, `ruta_archivo`, `tipo_mime`, `tamanio`, `created_at`.

### 4.8 `alertas` (`Alerta`)

`nota_id`, `tipo`, `descripcion`, `leida`, `usuario_asignado_id`, `created_at`.

### 4.9 `importaciones` (`Importacion`)

Log de importaciones: `usuario_id`, `nombre_archivo`, contadores, `estado` (`COMPLETADA` | `FALLIDA` | `PARCIAL`), `observaciones`, `created_at`.

### 4.10 `parametros` (`Parametro`)

`clave` (única), `valor`, `descripcion`, `updated_at`.

### 4.11 Tablas estándar Django

Además existen (migraciones Django): por ejemplo `django_session`, `django_migrations`, `django_content_type`, `auth_permission`, tablas de grupos si se usan, etc. El usuario de login **no** está en `auth_user` sino en **`usuarios`** (`AUTH_USER_MODEL = 'pagina.Usuario'`).
